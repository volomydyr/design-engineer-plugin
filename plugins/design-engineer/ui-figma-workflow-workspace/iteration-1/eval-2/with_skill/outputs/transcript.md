# Eval 101 — With Skill Transcript

**Prompt:** I have 30+ Figma frames for every possible state of every screen. My developer says this is overkill for AI-assisted development. Is he right? How should I restructure my Figma work?

**Step 1:** Skill confirms the developer is right. 30+ frames is 4-6x more than AI-assisted development needs. Most frames provide redundant visual information.

**Step 2:** Explains why: AI infers state variations (hover, active, disabled, error, loading) from the visual style of default states. Designing each state individually is wasted effort.

**Step 3:** Reviews the 30+ frames and identifies which 6 key screens capture all unique visual patterns: primary dashboard, detail view, form flow, empty state, modal, and navigation.

**Step 4:** Creates restructuring plan: move 6 key frames to a "Style Guide" page, archive remaining 24+ frames to a "Reference" page for historical context.

**Step 5:** Teaches the going-forward workflow: design one key screen per new feature, let AI generate all state variations and responsive breakpoints.

**Step 6:** Provides prompting strategy for getting AI to generate consistent state variations from minimal Figma input.

**Result:** Validated developer's assessment, identified 6 key screens to keep, restructured Figma file, and established minimal going-forward workflow.
