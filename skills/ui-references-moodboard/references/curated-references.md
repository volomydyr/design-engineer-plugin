# Curated Reference Apps

Seed references for users who skip the references-moodboard skill or do not know which apps in their domain are worth studying. These are not requirements – pick what fits your product, override anything that does not.

The pattern: each app has a specific quality worth studying. **Do not copy layouts wholesale.** Copy the principle behind why that app's choice works.

---

## Mobile event / social

**Partiful** – Conversational copy ("you're going" not "RSVP'd"), layered surfaces, custom illustrations, no emoji as illustration. Study: how copy carries the brand without the brand being literal.

**Luma** – Editorial typography, restrained palette per event (each event has its own color world), no defaulting to brand purple everywhere. Study: how to let user content (the event) own the visual identity.

**Lunchclub** – Photo-led, generous whitespace, very little chrome. Study: when to remove all decorative UI and let content carry the page.

---

## Mobile productivity

**Things 3 (iOS)** – A single ambient yellow accent that means "today" – used sparingly, never decorative. Custom typography at every size. Study: how restrained color use creates hierarchy.

**Linear (mobile)** – Monospace numerics, dense data without feeling crowded, no generic icons (every icon is a custom Linear-style glyph). Study: how typography choice communicates "this is a tool for engineers."

**Cron / Notion Calendar** – Borders only, no shadows, density that respects power-user workflows. Study: depth via tonal shifts, not elevation.

---

## Mobile fintech

**Lunchmoney** – Spreadsheet aesthetic done well – borders, dense rows, monospace numbers, minimal chrome. Study: when "looks like a spreadsheet" is a feature, not a bug.

**Copilot Money** – Card-based but each card has a different size and density based on its content (cash flow card ≠ subscription card). Study: how to break the identical-card-grid anti-pattern.

**Monarch Money** – Restrained palette (no blue/green primaries), content-first hierarchy. Study: a fintech app that does not reach for default fintech blue.

---

## Mobile health / fitness

**Strava** – Numbers as art (custom-sized stat displays, bold weights, no generic "metric card"). Map as hero. Study: how data display can be a brand element.

**Whoop** – Dark mode that actually feels like night use, recovery-themed reds and ambers (not generic neon), narrative in the data. Study: dark mode done as a design choice, not a color inversion.

**Oura** – Subdued color world (warm earth tones, never generic teal/green), photographic illustrations of bodies/states. Study: how to communicate "wellness" without the cliché wellness palette.

---

## Web SaaS dashboards

**Linear** – Density done right. Custom monospace, very tight spacing, every interactive state designed. Study: how a power tool can still be beautiful.

**Vercel** – Monochrome palette with one amber accent, generous typography scale, custom illustration system. Study: how to do "tech" without defaulting to blue.

**Stripe (dashboard)** – Restrained color, lots of editorial typography, content-led hierarchy. Study: balancing data density with breathability.

---

## Web fintech

**Mercury** – Editorial typography that says "we are not a bank app" – Calibre as the heading face, generous spacing, restrained palette. Study: how typography choice positions the brand against incumbents.

**Brex** – Saturated single-color palette per surface (each section has its own dominant color), bold display type. Study: how to use color to wayfind without relying on icons.

**Ramp** – Magazine-like layouts (asymmetric grids, hero photography, editorial copy). Study: how a fintech app can feel like a publication.

---

## Web content / media / personal

**Are.na** – Library aesthetic, minimal chrome, content-first density, system fonts used with purpose. Study: when default fonts ARE the design choice (the "we are infrastructure" stance).

**Read.cv** – Single sans typeface, generous line-height, one accent color per profile chosen by the user. Study: design as scaffolding for user-generated content.

**Pitch (decks)** – Editorial layouts, custom illustration, no template-ness despite being a template app. Study: how to do "professional but not boring."

---

## macOS / native desktop

**Things 3** – Native macOS HIG done with personality. Yellow today-accent, no skeuomorphism, no glassmorphism overuse. Study: how native ≠ generic.

**Reflect** – Dark mode that feels like a notebook, not a terminal. Custom illustration system. Study: how a productivity app can feel personal.

**Cron / Notion Calendar (desktop)** – Borders-only depth, dense data, no shadows. Study: how desktop apps can be dense without feeling cluttered.

**Raycast** – Custom monospace, command-palette-as-product, rich keyboard hierarchy. Study: how to design a power-user tool without scaring beginners.

---

## How to use this file

1. Find the category closest to your product type.
2. Read the "Study" notes – those are the principles, not the visual to copy.
3. Pick 2–3 apps that match your product's intent (warm vs cold, dense vs spacious, etc.).
4. Open the actual apps. Look at them. Take notes on specific elements that work.
5. Add your selections to `design/craft/references/references.md` with the SAME format ("from [app], take [specific quality]").

These references are anchors against AI defaults. The plugin's anti-patterns catalog tells you what NOT to do; this file tells you what excellent design looks like in your domain. Use both.
